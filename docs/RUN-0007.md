# Running 0007 in Supabase

The steps to run `docs/proposed-0007-logs-watchlist.sql` on the live database once you've agreed to it, and to check it
worked. About ten minutes. Every query below was run on a local Postgres 16 with migrations `0001` to `0006` (see
`docs/proposed-0007.md`); the results shown are what they printed there.

Nothing on the live site changes until `letterboxd-flow` is merged into `main` (see `docs/LAUNCH.md`): the live pages
don't ask for these tables. The branch's pages do, and use them as soon as they exist.

## 1. Check the database is ready

Supabase dashboard → project **shelfstackd** → **SQL Editor** → **New query**. Paste, then **Run**:

```sql
select
  exists (select 1 from pg_proc where oid = to_regprocedure('public.check_shelf_pro()') and prosrc like '%opacity%') as has_0004,
  exists (select 1 from information_schema.columns where table_schema = 'public' and table_name = 'shelves' and column_name = 'name') as has_0005,
  to_regprocedure('public.feed(text,timestamptz,uuid,integer)') is not null and to_regclass('public.follows') is not null as has_0006,
  to_regclass('public.logs') is null as not_run_yet;
```

You want one row, all four `true`.

- `has_0004`, `has_0005` or `has_0006` is `false`: stop. Run that migration from `supabase/migrations/` first (and its
  test), then come back here.
- `not_run_yet` is `false`: 0007 is already in. Skip to step 4.

## 2. Run 0007

**New query**. Open `docs/proposed-0007-logs-watchlist.sql`, select all of it, paste, **Run**. The comment block at the
end (one shelf each as a database rule) is commented out and does nothing.

- If the editor warns about a destructive operation (the file has `delete` inside its trigger functions), choose to
  run it anyway.
- You want **"Success. No rows returned"**.
- If it shows an error, nothing was changed: the whole file is one transaction. Copy the error into a session and stop
  here.

## 3. Let the API see the new tables

**New query**, **Run**:

```sql
notify pgrst, 'reload schema';
```

Supabase usually does this by itself after a change; this makes sure, so the pages don't get "not found" for a minute.

## 4. Check it's all there

**New query**, **Run**:

```sql
select
  (select count(*) from pg_class c where c.oid in (to_regclass('public.logs'), to_regclass('public.watchlist'), to_regclass('public.friend_hides'), to_regclass('public.log_counts')) and c.relrowsecurity) = 4 as tables_with_rls,
  to_regprocedure('public.activity(text,timestamptz,uuid,integer)') is not null and to_regprocedure('public.from_friends(integer)') is not null as functions,
  has_function_privilege('anon', 'public.activity(text,timestamptz,uuid,integer)', 'execute') as feed_for_visitors,
  not has_function_privilege('anon', 'public.from_friends(integer)', 'execute') as from_friends_signed_in_only,
  not has_table_privilege('authenticated', 'public.log_counts', 'select') and not has_table_privilege('anon', 'public.log_counts', 'select') as counts_kept_private,
  exists (select 1 from pg_trigger where tgname = 'follows_unkeep') as unfollow_trigger;
```

You want one row, all six `true`. Any `false`: run the undo in step 8 and bring the row into a session.

## 5. Run the tests

Both make throwaway users inside a transaction and roll everything back, so nothing is kept.

1. **New query**: paste all of `docs/proposed-rls_phase4.sql`, **Run**. The last result should be
   **`ALL PHASE 4 CHECKS PASSED`**. A failed check stops with an error that starts `FAIL:`.
2. **New query**: paste all of `supabase/tests/rls_phase3.sql`, **Run**. The last result should be
   **`ALL PHASE 3 CHECKS PASSED`** (0007 adds a trigger to `follows`, so this checks follows still behave).

What the phase 4 test can't do in the SQL Editor is two sessions at once. That was checked locally: two adds at the
same moment, one holding its transaction open, ended at 6 on the watchlist and 50 logs (without the locks, 7 and 51).

## 6. Check from outside, as a visitor

In Git Bash, from the repo's folder (the key is the public publishable one the pages use, read from `index.html`, so
nothing secret is typed or printed):

```bash
KEY=$(grep -o 'sb_publishable_[A-Za-z0-9_-]*' index.html | head -1)
API=https://fiukspnovrlzlcdekcnb.supabase.co/rest/v1

# the feed: a list, starting with [ (before 0007 this was {"code":"PGRST202",...})
curl -s "$API/rpc/activity" -H "apikey: $KEY" -H "Content-Type: application/json" -d '{"scope":"everyone","n":3}'; echo

# From friends is for signed-in people only: "permission denied for function from_friends" (code 42501)
curl -s "$API/rpc/from_friends" -H "apikey: $KEY" -H "Content-Type: application/json" -d '{}'; echo

# the day's log counts are the database's own: "permission denied for table log_counts" (code 42501)
curl -s "$API/log_counts?select=*" -H "apikey: $KEY"; echo
```

## 7. Put the files where migrations live

Tell a session it's run, or do it yourself on `letterboxd-flow`:

```bash
git mv docs/proposed-0007-logs-watchlist.sql supabase/migrations/0007_logs_watchlist.sql
git mv docs/proposed-rls_phase4.sql supabase/tests/rls_phase4.sql
```

Then the README's Accounts section and `docs/HANDOFF.md` should say 0007 is in, and the header of the moved SQL file
should lose its "NOT RUN" paragraph. A session can do all of that in one commit.

## 8. If it has to come out again

This takes out everything 0007 added, logs and watchlists included, and leaves 0001 to 0006 as they were. It was run
locally after 0007: nothing was left, `rls_phase3.sql` passed, and 0007 could be run again afterwards.

```sql
begin;
drop function if exists public.activity(text, timestamptz, uuid, int);
drop function if exists public.from_friends(int);
drop trigger if exists follows_unkeep on public.follows;
drop function if exists public.follows_unkeep();
drop table if exists public.friend_hides, public.log_counts, public.watchlist, public.logs;
drop function if exists public.logs_before_insert(), public.watchlist_before_insert(), public.logs_off_watchlist(), public.friend_hides_before_insert();
drop function if exists public.title_key(text, text, smallint);
commit;
notify pgrst, 'reload schema';
```

The pages go back to shelves only by themselves: they treat "not found" as "not there yet".
